# P11 durable CSV exports and SSE

## Acceptance and ownership
GET /v1/shipments?export=1 preserves the exact HTTP 202 body {"message":"we start to process data"}. It accepts all existing Tracking filters and sort parameters, rejects page/length and duplicate singleton/unknown parameters, and uses verified active shipper membership. Cookie acceptance additionally requires X-Requested-With: logistics-web and an allowed Origin when present, because this approved GET starts durable work. Bearer clients need no custom header; credentials never appear in URLs. It commits a job before responding and does not execute the package query or generate CSV synchronously.

The export_jobs table (Alembic 0007_exports) retains company/requester, normalized filters with explicit effective UTC dates, state/attempt/backoff, sanitized reason code, artifact metadata and optional dismissal time. A composite requester/company FK enforces membership association. A requester advisory lock bounds outstanding undismissed jobs to 50, including completed jobs; 429 asks the requester to dismiss completed exports before adding more. This is an engineering resource bound. Dismissing is idempotent, permitted only for ready/failed jobs, and hides a notification without deleting the job/file. Both administrator and user can export; neither can see another user's jobs/files, including within the same company.

## Worker and actual storage
The optional exports Compose profile runs python -m app.exports.cli run; once performs one scan. PostgreSQL is the durable queue. Each scan claims at most 20 due IDs. A per-job PostgreSQL session advisory lock prevents concurrent generation. Attempts and backoff commit before generation; crashes count toward five attempts with 5/30/120/600/1800-second scheduling. Temporary filesystem/database failures retry; invalid state/paths, unauthorized requester and output bounds fail safely. Failed exports have no download URL. A ready job is never regenerated by polling, reconnect, notification recovery or a repeated worker call.

The worker rechecks active requester membership, then reads packages at execution time in one repeatable-read snapshot using the exact shared Tracking filter builder. Accepted dates do not shift overnight. Area IDs are validated active/owned at acceptance and retained as accepted predicates even if an area is subsequently soft-deleted. Deleted-area labels are still enriched. No request-time frozen package set is claimed. Stable package-ID order is an engineering output choice; list sorting does not change membership. Results use a PostgreSQL server cursor/yield_per=500, incremental csv.writer and bounded hash/download chunks; no full row list/file is held in worker memory. A 250,000,000-byte output ceiling fails rather than truncating. Execution time, aggregate storage quota and production concurrency budgets remain deployment/P12 work.

The seven columns, in order, are shipment_number,carrier,route,order_date,due_date,pod_name,deliver_time. Carrier is company.name, route is readable area.name (including deleted labels), dates use ISO calendar format, delivery uses the existing recipient offset-aware display contract with UTC fallback. NULL is empty; zero/leading-zero strings are retained. Python CSV handles commas, quotes and newlines. Potential spreadsheet formulas/control-prefixed cells receive a leading apostrophe in the exported cell; canonical data is unchanged. Stored order_date is never synthesized from processing time.

Development writes an actual UTF-8 CSV under sftp/download/{job-UUID}/shipment-{UTC-generation-date}.csv. Downloads are separate from intake folders. A unique job directory prevents same-day collisions. The worker flushes/fsyncs a private temporary file, hashes it, atomically publishes and fsyncs its directory, then commits ready metadata. A crash after publication can replace that nonready job's file on retry; ready artifacts are never overwritten by worker retries. Interrupted .part files and failed-job output may require trusted operator cleanup after confirming the job is inactive; there is no automatic deletion/retention policy. Directory/name/UUID checks and non-following regular-file opens reject traversal/symlink targets. The API mounts only the download root read-only, and authenticates each download. Missing/size-mismatched files return sanitized 503; they do not trigger notification-driven regeneration.

The returned local URL /v1/exports/{UUID}/download is a working authenticated local adapter URL. No external upload/public S3 object is claimed. Future public S3 storage remains the approved production target and requires separate configuration.

## API and notification contracts
All routes below reject query parameters, require live verified shipper authentication, and use no-store. UUIDs are opaque lookup identifiers, not authorization.

| Route | Response |
|---|---|
| GET /v1/exports | {items:[ExportStatus]} for this requester's undismissed jobs, oldest first, maximum 50 |
| GET /v1/exports/{UUID} | ExportStatus, including dismissed jobs when accessed by their owner; foreign/unknown 404 |
| POST /v1/exports/{UUID}/dismiss | {"message":"Export dismissed"}; cookie CSRF guard applies; pending/retry_wait 409 |
| GET /v1/exports/{UUID}/download | Actual CSV attachment only when ready; nonready 409, foreign/unknown 404, unavailable file 503 |
| GET /v1/exports/events | Authenticated text/event-stream; allowed Origin guard, no URL token/company scope |

ExportStatus is {id:UUID,state:pending|retry_wait|ready|failed,created_at:aware-ISO,url:string|null,row_count:integer|null,reason_code:string|null}. URL and row_count become available only in ready state. Internal paths, filters, source records and provider exception messages are not in notification/status DTOs. OpenAPI defines the response models and typed errors.

The SSE stream sends retry:3000 and event:exports with the complete requester-scoped ExportList snapshot on connection and each change; otherwise it sends event:heartbeat with an empty data object. It polls durable PostgreSQL state every two seconds, so Redis notification outages cannot lose readiness. This engineering baseline adds no pub/sub dependency. Each iteration re-authenticates the original token for expiry/revocation/live membership. session-expired closes the UI stream and expires the workspace; unavailable closes the server stream after a sanitized event so native EventSource can reconnect. Clients do not need Last-Event-ID: every new connection replays current undismissed state. Dismissal persists across reload; delivery is replayable state, not an exactly-once message claim.

## Frontend
Tracking's Export CSV submits all committed filters with export=1 and removes pagination. A synchronous click guard avoids overlapping submits. Acceptance shows the exact supplied message; it does not create a ready link. The workspace maintains one cookie-authenticated EventSource across navigation, recovers through REST on mount/open/focus/visible return and after acceptance, and offers manual Refresh exports on disconnection/error. Ready cards are polite live announcements with the exact clickable text Click here to download. Pending/retrying and failed states have no link. Snapshot replacement deduplicates replay; durable dismissal and a local in-flight guard prevent old snapshots from resurrecting a dismissed card. Runtime validation restricts returned links to the exact same-origin owner-checked download path. Workspace remounts/aborts close streams and discard late responses after session/company/user changes. No bearer is stored in JavaScript or query parameters.
